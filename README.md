# 네이버 톡톡 FAQ 챗봇

## 서버 상태 확인

Render에 배포한 뒤 다음 주소를 브라우저에서 열어 서버와 FAQ 상태를 확인할 수 있습니다.

- `https://<Render 서비스 주소>/monitor` — 서버 상태와 FAQ 수, 톡톡 요청·응답 통계를 카드와 그래프로 보여주는 대시보드입니다. 상태와 응답 카운터는 한 번의 요청으로 함께 읽고, 탭이 보일 때 1시간마다 갱신합니다. 다른 탭을 보거나 창을 숨기면 자동 조회를 중지합니다. 그래프는 페이지를 열어 둔 동안 요청 추이를 수집합니다.
- 대시보드의 **미등록 안내**, **무시된 이벤트**, **처리 오류** 숫자를 누르면 해당 톡톡 질문 기록을 볼 수 있습니다. 질문 원문은 개인정보일 수 있어 관리자 계정(`ADMIN_USER`, `ADMIN_PASSWORD`)으로 인증해야 합니다. 최근 100건을 현재 Render 인스턴스 메모리에만 보관하므로, Render가 절전되거나 재시작되면 기록이 사라질 수 있습니다. PC를 계속 켜 둘 필요는 없습니다.
- `https://<Render 서비스 주소>/health` — FAQ 파일을 읽고 형식을 확인합니다. 정상일 때 HTTP `200`, 문제가 있을 때 `503`과 상태 정보가 표시됩니다. Render의 **Settings → Health Check Path**에도 `/health`를 지정하면 배포 후 상태 확인에 사용할 수 있습니다.
- `https://<Render 서비스 주소>/metrics` — Prometheus 텍스트 형식의 상태와 웹훅 처리 통계를 제공합니다. Prometheus를 사용하는 경우 이 주소를 scrape 대상으로 등록하세요. 통계는 메모리에 누적되므로 서버가 재시작되면 초기화됩니다.

`chatbot_faq_ready`가 `0`이면 FAQ 파일이 없거나 형식 오류가 있는 상태입니다. `chatbot_webhook_requests_total`은 네이버에서 도착한 웹훅 요청 수이며, `chatbot_webhook_responses_total`은 답변 성공(`answered`), 미등록 안내(`fallback`), 무시(`ignored`), 처리 오류(`error`)로 나뉩니다. `chatbot_last_webhook_timestamp_seconds`가 갱신되지 않는다면 네이버에서 웹훅이 도착하지 않는지 확인하세요.

## 질문·답변 수정 페이지 설정

관리자 편집 페이지는 `https://<Render 서비스 주소>/admin`에서 사용할 수 있습니다. Render 대시보드의 **Environment**에 다음 환경변수를 등록한 뒤 서비스를 재배포하세요.

| Key | Value |
|---|---|
| `ADMIN_USER` | 편집 페이지 로그인 이름 |
| `ADMIN_PASSWORD` | 충분히 길고 추측하기 어려운 편집 페이지 비밀번호 |
| `GITHUB_TOKEN` | 아래 안내에 따라 만든 GitHub 토큰 |
| `GITHUB_REPOSITORY` | `breakouthongdae-rgb/breakout_hongdae_navertoktokchatbot` 형식의 저장소 경로 |
| `GITHUB_BRANCH` | `main` |

`GITHUB_TOKEN`은 GitHub에서 해당 저장소만 접근하도록 **Fine-grained personal access token**을 만들고, **Contents: Read and write** 권한만 부여하세요. 토큰은 코드나 채팅에 붙여 넣지 말고 Render 환경변수에만 저장하세요. 토큰을 공개했거나 실수로 코드에 올렸다면 GitHub에서 폐기하고 새로 발급하세요.

설정을 마치면 `/admin`에 접속해 로그인하고 텍스트를 수정한 뒤 **저장**을 누릅니다. 저장하면 GitHub의 `talk.txt`와 `faq_examples.txt`가 질문 목록에 맞춰 함께 갱신되고, Render 자동 배포가 완료된 후 새 답변이 적용됩니다. 새 질문은 빈 예시 목록으로 만들어지며, 삭제한 질문의 예시는 파일에서 제거됩니다. 질문 제목을 바꾸면 새 질문으로 처리되므로 기존 예시 문장은 새 제목으로 이동되지 않습니다.

## 답변 형식

관리자 편집 페이지에서는 질문과 답변을 별도 칸에 입력하고, 답변의 줄바꿈과 문단도 그대로 작성할 수 있습니다. 저장된 `talk.txt`에서는 줄바꿈이 `\n`으로 표시됩니다.

파일을 직접 편집할 때는 한 줄에 질문과 답변을 작성하고 첫 번째 `:`로 둘을 나눕니다. 답변의 여러 줄은 `\n`으로 표시하거나 다음 줄에 이어서 입력할 수 있습니다.

```text
영업시간이 언제인가요? : 평일 오전 9시부터 오후 6시까지 운영합니다.
예약은 어떻게 하나요? : 원하시는 날짜와 시간을 알려주세요.
긴 답변 예시 : 첫 번째 문단입니다.\n\n두 번째 문단입니다.
```

빈 줄과 `#`으로 시작하는 줄은 무시됩니다. `faq_examples.txt`에는 `talk.txt`의 질문 제목별로 고객이 보낼 수 있는 다른 표현을 `|`로 구분해 추가할 수 있습니다. 관리자 페이지에서 질문을 추가하거나 삭제하면 이 파일의 항목도 저장 시 자동 동기화됩니다. 질문 제목과 예시 표현, 답변 내용의 단어를 비교해 답변을 찾으며, 일치도가 낮거나 여러 항목이 비슷하면 기본 미등록 안내를 반환합니다. 이 방식은 문장 예시와 단어를 비교하는 것으로, 임베딩 벡터나 AI 의미 검색은 아닙니다. 실제 의미 검색을 도입하려면 임베딩 모델/API 연동이 별도로 필요합니다.
